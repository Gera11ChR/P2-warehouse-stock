# .agents.md — AI Agent Governance & Operational Directives

## Project Overview
**DMS-TELECOM (P2 Monorepo Consolidation)**  
DMS-TELECOM is an enterprise-grade fiber optic logistics, warehouse, and fleet inventory management system. It governs material lifecycles, stock movements, and physical hardware allocations across warehouses, teams (`Equipos`), and field crew vehicles (`Fibra Óptica`).

---

## 1. Document Authority Hierarchy

All AI sub-agents MUST strictly adhere to the following 5-level hierarchy. Lower levels must never contradict higher levels.

*   **Level 1 — Supreme Authority:** `docs/constitution.md` (Business, security, and architectural invariants).
*   **Level 2 — Operational Governance:** `docs/flujo_operacional.md` and `.agents.md` (Workflow, agent responsibilities, and execution pipelines).
*   **Level 3 — Active Change Package (Udoc2):** `openspec/changes/<active-change>/` (`proposal.md`, `EARS.md`, `issues-breakdown.md`). The operational source of truth for the active initiative.
*   **Level 4 — Derived Execution Documents:** `constitution-impact.md` and `tasks.md`. (Translates Udoc2 into executable work).
*   **Level 5 — Implementation Artifacts:** Code in `backend/`, `frontend/`, and `tests/`.

---

## 2. Core Operational Guardrails

1.  **Specification Before Implementation:** No code shall be created or modified without an approved Udoc2 package and task decomposition.
2.  **Backend-First Rule:** Frontend implementation is strictly blocked until backend specifications, database designs, and API contracts are fully validated and approved. Frontend SHALL NOT redefine backend behavior.
3.  **Constitution Supremacy:** Direct inventory mutations that bypass the immutable ledger, audit records, authorization, or transaction boundaries are strictly forbidden.
4.  **Requirement-Based Verification:** Tests exist to verify specific EARS requirements, not implementation details. 
5.  **Traceability Requirement:** The following unbroken chain MUST exist and be validated before coding begins: `Issue` → `Proposal Item` → `EARS Requirement` → `Task` → `Implementation` → `Test`.

---

## 3. SDD Execution Pipeline & Gates

Agents must execute tasks through the 7-Phase SDD Pipeline (`flujo_operacional.md`), respecting the following mandatory gates:

*   **Pre-Phase Validation Gate (Udoc2):** Work cannot begin until `proposal.md`, `EARS.md`, and `issues-breakdown.md` exist and are fully traceable.
*   **Constitutional Review Gate (Phase 1):** Phase 2 (Data, Schemas & Security) is blocked until `constitution-impact.md` is generated and approved.
*   **Definition of Done (DoD) Gate:** A change is only complete when all Udoc2 requirements are implemented, the Traceability Matrix is complete, all tests (pytest/mypy) pass without regression, and the architecture is formally signed off and archived.
