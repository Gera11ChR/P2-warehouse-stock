## MANDATORY AUDIT VECTORS (COMPLIANCE MODE)

### 1. Entity Mapping & Nomenclature (Entity Drift)
- **Active Spec Compliance:** Validate that entities and relationships match the *currently approved* OpenSpec package and DDL. Do not enforce legacy patterns if the active OpenSpec dictates a different domain structure.
- **Soft Delete:** Ensure that catalog entity deactivations consult and modify the soft-delete flag dictated by the approved DDL. Physical deletions (`DELETE FROM`) are strictly prohibited for catalog entities.

### 2. Transactional Integrity & Stored Functions (Logic Drift)
- **Movement Confirmations:** Verify that confirmation endpoints explicitly execute the processing Stored Function dictated by the active OpenSpec `domain_rules.transaction_delegation`. Reject if Coder attempts direct inventory subtraction/addition in Python.
- **Reversals & Cancellations:** Validate that cancellation flows invoke the cancellation Stored Function dictated by the active OpenSpec `domain_rules`.
- **Stock Adjustments:** Validate that administrative manual stock edits invoke the adjustment Stored Function dictated by the active OpenSpec `domain_rules` to ensure audit ledger entries are generated. Direct `UPDATE` to stock balances is forbidden.
  `[Ejemplo Puramente Ilustrativo - Sujeto a Especificación Normativa]` (e.g., delegations such as `fn_procesar_movimiento`, `fn_cancelar_movimiento`, `fn_ajustar_stock_almacen` reflect a past contract; the authoritative list lives in the active OpenSpec).

### 3. Database Exception Handling (Exception Drift)
- Validate that errors thrown by Stored Functions (e.g., *"Stock insuficiente..."*) are caught and mapped to HTTP `400 Bad Request` or `422 Unprocessable Entity`.
- Reject API controllers that leak native SQL exceptions (HTTP `500 Internal Server Error`).

### 4. Traceability & Bulk Uploads (Traceability Drift)
- **JSONB Format:** Confirm audit logs (the audit ledger table dictated by the approved DDL) enforce the standardized payload structure (`modulo`, `accion`, `valores_anteriores`, `valores_nuevos`) mandated by the active OpenSpec contract.
- **Import History:** Verify CSV, XLSX, and XML ingestion persists records in the import-history table dictated by the approved DDL with JSON error details.
