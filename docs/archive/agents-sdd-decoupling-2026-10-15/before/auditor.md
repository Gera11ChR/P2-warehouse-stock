## MANDATORY AUDIT VECTORS (COMPLIANCE MODE)

### 1. Entity Mapping & Nomenclature (Entity Drift)
- **Active Spec Compliance:** Validate that entities and relationships match the *currently approved* OpenSpec and DDL (e.g., `secciones_inventario`, `inventario_equipos`). Do not enforce legacy patterns if the active OpenSpec dictates an isolated inventory domain.
- **Soft Delete:** Ensure material, category, or team deletions consult and modify the `is_active = FALSE` flag. Physical deletions (`DELETE FROM`) are strictly prohibited for catalog entities.

### 2. Transactional Integrity & Stored Functions (Logic Drift)
- **TEAMS / DEVOL Confirmations:** Verify that confirmation endpoints explicitly execute `SELECT fn_procesar_movimiento(:movimiento_id)`. Reject if Coder attempts direct inventory subtraction/addition in Python.
- **Reversals & Cancellations:** Validate that cancellation flows invoke `SELECT fn_cancelar_movimiento(:id, :usuario, :motivo)`.
- **Stock Adjustments:** Validate that administrative manual stock edits invoke `SELECT fn_ajustar_stock_almacen(...)` to ensure audit ledger entries are generated. Direct `UPDATE` to stock balances is forbidden.

### 3. Database Exception Handling (Exception Drift)
- Validate that errors thrown by Stored Functions (e.g., *"Stock insuficiente..."*) are caught and mapped to HTTP `400 Bad Request` or `422 Unprocessable Entity`.
- Reject API controllers that leak native SQL exceptions (HTTP `500 Internal Server Error`).

### 4. Traceability & Bulk Uploads (Traceability Drift)
- **JSONB Format:** Confirm audit logs (`auditoria_eventos`) enforce the standardized payload (`modulo`, `accion`, `valores_anteriores`, `valores_nuevos`).
- **Import History:** Verify CSV, XLSX, and XML ingestion persists records in `historial_importaciones` with JSON error details.
